# 웹에서 글과 카테고리 편집하기

## 연결

이 사이트는 [Pages CMS](https://app.pagescms.org/)의 웹 편집 화면을 사용합니다. 저장 대상은 `mldlcl2022/mldlcl2022.github.io` 저장소의 `main` 브랜치입니다. 편집 설정은 저장소 루트의 `.pages.yml`에 있습니다.

1. `main`에 CMS 설정이 반영된 뒤 Pages CMS에서 GitHub 계정으로 로그인합니다.
2. GitHub App 설치 화면에서 **이 저장소 하나만** 선택합니다. 앱 권한을 확인한 후 연결합니다.
3. 저장소와 `main` 브랜치를 열고 **기술 글** 또는 **카테고리**를 선택합니다.

Pages CMS는 별도 로그인 화면과 편집기를 제공합니다. 공개 사이트에는 관리자 링크를 추가하지 않았습니다. GitHub 토큰과 앱 비밀 값은 사이트 코드에 넣지 않습니다.

## 글 작성과 발행

- **기술 글**에서 제목, 설명, 작성일, 선택적 작성 시간, 카테고리, 본문을 입력합니다. 본문은 서식 편집과 Markdown 원문 전환을 지원합니다. 이미지는 `public/images/blog/`에 저장되어 `/images/blog/`로 표시됩니다.
- 새 글은 **비공개 초안**으로 시작합니다. 이 상태로 저장하면 GitHub에는 커밋되지만 공개 블로그 목록과 상세 페이지에서는 제외됩니다.
- 공개할 때 **비공개 초안**을 끄고 저장합니다. `main`에 커밋된 후 GitHub Actions의 **Deploy to GitHub Pages**가 성공하면 사이트에 표시됩니다. 저장과 공개 배포는 별도 단계입니다.
- 기존 글 파일명과 `/blog/<파일명>/` 주소는 유지합니다. 글 파일 이름 바꾸기는 편집기에서 막아 두었습니다.
- 본문 편집기의 미리보기는 콘텐츠를 확인하는 용도입니다. 실제 사이트 화면은 로컬 미리보기 또는 배포 후 사이트에서 확인합니다.

## 카테고리

- **카테고리**에서 새 항목을 추가하고, 필요하면 상위 카테고리를 지정합니다. 계층은 두 단계까지 지원합니다. 글의 **카테고리** 입력은 등록된 항목에서 선택합니다.
- 새 카테고리는 글이 하나 이상 연결되어야 공개 목록에 나타납니다. 빈 분류를 숨기는 기존 디자인을 유지합니다.
- 기존 카테고리의 이름을 바꾸려면 연결된 글과 하위 카테고리의 참조도 함께 수정해야 합니다. 검증이 맞지 않으면 배포가 중단됩니다.
- 삭제하려면 카테고리 편집 화면의 **비어 있는 카테고리 삭제** 동작을 사용합니다. 글 또는 하위 카테고리가 남아 있으면 삭제하지 않습니다. 먼저 글을 재분류하고 하위 항목을 정리하세요. 일반 삭제 버튼은 비활성화되어 있습니다.

## 로컬 확인

```powershell
pnpm validate:content
pnpm test:categories
pnpm check
pnpm build
pnpm verify:build
```

기존 HOME 애니메이션과 방문자 집계 코드는 CMS가 수정하지 않습니다. 로컬 미리보기는 운영 방문 횟수를 늘리지 않고 통계만 읽습니다.
